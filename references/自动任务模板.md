# 自动任务模板（动作 01 · 第 4 步）

> 用 `automation` 工具创建/更新。**create / update 只产待确认建议**，用户点确认或回 `/apply [短码]` 才落库（回"确认"二字无效）。
> 建之前先 `automation action=list` 看有没有同名任务：**无 → create；有 → update（附 id）覆盖 prompt**，别 create 出双份。

## 设计原则（本版核心）

- **根是动态的**：任务不写死单一工作台。开工先读 `studio-mounts.json`，取**全部 `status=active` 且带 write 的挂载根**（主工作台 + 外部文件夹）——用户新加挂载即自动纳入，无需改 prompt。
- **按使用情况分级**：每个根算「最近活跃度」，活跃根深扫、休眠根轻扫，不浪费预算也不漏活。
- **写权限按法域分**：主工作台可写（safe 档搬反悔区）；**外部根默认零写入**（只读巡检出方案 + notify，执行需另行授权）。
- **无引擎**：所有扫描/搬移用现场命令（`Get-ChildItem` / `Move-Item`），阈值按 `<根>\.optimize\rules.json` 或 skill `engine/rules.default.json`（内置）判断。

## 建议参数

```
action:       create（无同名任务）｜ update（已有同名任务，附 id）
scheduleType: cron
schedule:     "30 5 * * *"          # 每日 05:30，可按用户习惯改
label:        每日治理巡检
prompt:       <下面的全文>
```

## prompt 全文（可直接粘贴）

```markdown
# 每日治理巡检（优化大师·多根版）

你正以本实例主 Agent 身份执行每日定时治理巡检。本 prompt 是「预先签发的落点授权书」：只授权下文写明的对象与通道，授权之外的写、搬、删一律不做。严格按步骤执行，**不要创建新的定时任务**。

## 第〇步：开工核对与根发现（硬闸）
1. `(Get-Location).Path` 核对（定时任务 cwd 可能漂移）；本轮所有命令一律使用**绝对路径**。
2. **动态发现管辖根**：读 `<HANA_HOME>\studio-mounts.json`（**用 UTF-8 读**：`[System.IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)`，否则中文路径会乱码、`Test-Path` 误判），取所有 `status=active` 且 `capabilities` 含 `list+read+write` 的挂载根：
   - **主工作台** = `desk.home_folder`（即 `<工作区>`）——**唯一允许写入的根**。
   - **外部根** = 其余 active 挂载（如 `<外部根>`）。
   - cwd 不等于任何管辖根 → 仍按绝对路径执行，另记异常并 notify。
3. 挂载表读不到 → 只扫主工作台、只报告、notify。**不得凭记忆回退旧根/旧映射。**

## 一、按使用情况分级（决定本轮深度）
对每个根，浅层（2 级）取最近改动时间，算活跃度：
- **活跃**（≤3 天有改动）→ 全流程（扫描 + safe 档搬反悔区 + 中风险出方案）
- **温**（3~30 天）→ 扫描 + 出方案，不搬
- **休眠**（>30 天）→ 轻扫（入口件 / 多版 `dist*` / 大文件 / 顶层散件），只提示
每根的分级结论写进检查点。**外部根无论活跃与否都只读**（见第三步）。

## 二、主工作台（全流程，唯一可写的根）
- **六格白名单**：`projects` `storage` `inbox` `_temp` `个性化` `.server`；**平台常驻户** `OH-Works` `OH-媒体库` `魔术卡`（出现即原地不动）。
- **规则源**：`<工作区>\.optimize\rules.json`（生命周期 / 白名单 / 保护区 / 护栏）。读不到 → 用 skill `engine/rules.default.json`；仍读不到 → 只报告。
- **扫描**：根顶层散件 + `_temp\<子目录>` 超龄（按 `tempLifecycle` 算天数）+ `inbox` 滞留（>14 天）。**禁递归全量列文件。**
- **判去向（四问）**：Q0 撞常驻户/保留名 → 就地不动；Q1 本地活 → `projects`；Q2 运维/产品线 → 外部根（本轮不执行）；Q3 临时件 → `_temp` 对应格；Q4 说不清 → `inbox`。
- **唯一存底先判**：在 `projects` / `storage\tools` 检索（文件名 + 首行特征），零命中 → 判「不可再生 / 唯一存底」→ 建议落 `projects\{项目}\docs\{原名}-待并入.md`，**绝不进时钟目录 / 反悔区 / 删除**。
- **执行（仅 safe 档）**：junk / pruneCheckpoints / 非豁免空目录 / 图片类 autoHome / `_temp` 超龄 → `Move-Item` 进 `_temp\反悔区\{批次}\` + 写 `.manifest.jsonl`（`{from,to,ts}`）。中风险档（散件 / `inbox` 滞留 / 存底超份）→ **只汇总待确认**。`oversized`（>50MB）**永不进删除计划**。
- **硬护栏**：单批 ≤30 项、体积 ≤200MB、涉及顶层 ≤2；执行前逐件 `Test-Path` 核源。

## 三、外部根（只读巡检 + 出方案，零执行）★
- **默认零写入**：不搬、不删、不改外部根任何文件；只读扫描 → 出三档方案 → notify。**执行需用户另行授权**（默认人执行）。
- **扫描面**（浅层，禁递归全量）：入口件（`README.md` + `项目说明.md`）、多版 `dist*`（历史份数 >2 即违例）、环境格（`node_modules` / `.venv`）、运行态（`world` / `data` / `logs` / `*.db`）、`_temp` 与临时件、顶层散件、大文件（>50MB）、路径腐烂（grep 旧路径）。
- **红线（绝不碰、不列删除）**：运行态格、**唯一存底**、`.git`、凭据（`.env` / `*.key` / `*.pem` / `secrets*`）、归档大件。
- **三档方案**：可现清（可再生：多版 dist 旧份、`node_modules`、临时件）/ 需确认（散件、路径腐烂、大件处置）/ 绝不碰（运行态、存底、凭据）。
- 出方案后 notify；**每根各自一份**，写进检查点。

## 四、本体——只读盘点，不执行
- `.hanako`（`<HANA_HOME>`）：**不执行任何删除 / 清理**；异常列入「本体异常报告」，移交「优化大师 · 03 整理」。

## 五、关联同步（十步）
对本轮**实际 moved** 的件，按序更新：① pinned 记忆 → ② 经验库 → ③ 其它 SKILL / README / 项目索引 grep 旧路径 → ④ `.optimize\rules.json` 归类表 → ⑤ cron prompt 与根 `AGENTS.md` → ⑥ 外部根内引用 → ⑦ 本体台账 → ⑧ git tag / 历史随迁 → ⑨ `preferences.json` → ⑩ `config.yaml` / `studio-mounts.json`。全部写入检查点「关联更新」表。

## 六、指针复核
记忆 / 经验里的路径、文件名、版本号逐条 `Test-Path` 实测：**只信实测不信记录**。结果写入「指针复核」表。

## 七、沉淀（检查点三表）
- 路径：`_temp\检查点\{YYYYMMDD}-归类检查点.md`（主工作台下）；已存在则追加不覆盖；正文用 write / edit，**禁 Add-Content**。
- 三表均含「**法域**」列（工作区 / 外部 / 本体）：操作记录 / 关联更新 / 指针复核。
- 每根的活跃度分级、外部根方案、confirm 待确认项、blocked 项 → 「待办裁决列表」＋notify。
- 无异常 → 一句「工作区很干净 ⭐」，安静结束。
```

## 失败分科（照 08 §6）

看 `cron-runs` 的 error 字段：

- **超时**（20 分钟墙）→ prompt 改分批 + 幂等 + 断点续扫。**多根尤其要分批**：一次只深扫一个活跃根，外部根宁可全量浅扫。
- **出生链断**（`source session unavailable`）→ **重建任务**（改 prompt 救不了出生地）。
- **cwd 漂移**（产物落非预期目录）→ 第〇步已拦；根治要重建任务。
- **模型 / 网关** → 换 `executor.model`。

> **多根与 20 分钟墙的关系**：根越多越要克制。原则——主工作台每轮必扫；外部根按"每轮浅扫全部"或"每天轮一个深扫"，**宁浅勿慢**。
