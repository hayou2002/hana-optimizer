# 通道与工具速查

> 三个动作里凡是要"动手"的地方，先来这张表找**唯一合法通道**。图形化工具与 CLI 并存时，优先用平台正式入口。
> **四个板块都要清理与整理**，只是执行通道不同——下面按板块列。

## 一、工作区（板块 1）

| 动作 | 通道 |
|---|---|
| 扫描 / 出方案 | 我（`ls`/`find`/`grep`/`exec_command` 现场盘点）＋ `rules.json` 阈值 |
| 执行（软删） | 我用 `exec_command` 搬进 `_temp/反悔区/{批次}/` ＋ 写 `.manifest.jsonl`（只搬不删） |
| 进保护区（projects/storage）的搬移 | 我用 `exec_command`（FULL 域）或 `file` copy＋删源 |
| 硬删（唯一删除口） | 用户明确同意后 `Remove-Item -Recurse`；先确认批次是到期件 |
| 交付物进会话 | `stage_files`（只报路径不算交付） |

## 二、专项工作文件夹（板块 2）

- 盘点 ＋ 出方案：现场只读盘点（`Get-ChildItem`）＋ Agent 出方案（只读）。
- **执行**：外部挂载带 write，**Agent 用 `exec_command`（FULL 域）按方案直清**；显式绝对路径、**一次一根**、全程留痕。
- 默认只清"可再生"项；运行态（`world`/`data`/`*.db`）与唯一存底**不删**；`.git` 与凭据不碰。
- 删除若需落地桶：用该域内自建 `_temp/`（**不要用本体 `trash/`**——它无 TTL、平台无出清）。要留退路先备份。

## 三、本体 / 拓展（板块 3）

| 动作 | 通道 |
|---|---|
| 盘点 ＋ 出方案 | 现场只读盘点（`Get-ChildItem`＋`Measure-Object`）＋ Agent 出方案 |
| 卸载 / 更新 / 启用停用扩展 | **`extension_manager`**（`kind=app|skill|recipe|connector|bundle`，`action=remove/update/disable/enable`）——**唯一合法通道，不手拷/手删目录** |
| 安装 / 更新本地包 | `extension_manager action=install/update`（产待确认建议，用户确认后落库） |
| 孤儿 `app-data/{id}`、黄门可再生项清 | 出方案 → 人/许可脚本清（**先退出 Hana**；`.cache`/`model-catalog`/`artifacts/staging` 属黄门） |
| **红门** | **绝不碰**（凭据 / 核心索引 / 内核 `artifacts/` 除 staging / `agents/` 正文 / `attachments/` / `checkpoints/` / `migration-backups/` / `user/*.json`）；本体无清理型反悔窗口，要留退路只能人工备份 |

## 四、经验记忆（板块 4）

| 需求 | 通道 |
|---|---|
| 查记忆 | `search_memory` |
| 置顶增删 | `pin_memory` / `unpin_memory`（无 update，改＝撤旧+存新；unpin 支持 keyword 批量命中） |
| 改记忆四段真源 | `PUT /memories/compiled/{facts,today,longterm,week/days/:date}` |
| 经验记 / 查 | `record_experience` / `recall_experience`（**无 delete/merge/move**，编辑删除只能改文件） |
| **整理（九项）** | 原生通道 ＞ **文件面（仅 `pinned.md`、`experience/*.md`）** ＞ 人工；方案见现场只读盘点 ＋ Agent 出方案 ＋ 07 九项（去重/合并/拆分/降权/退役/删除/消冲突/类目/格式） |
| 整库重置 | `DELETE /memories`（"忘掉"时用，须用户明确） |
| 看自动整理是否在跑 | `GET /memories/health`、`dream/state.json` |

**红线**：不手改 `memory.md`/`week.md`/`experience.md`（派生）；不动 `facts.db` 的 `-wal/-shm`；**取代 ≠ 删除**（矛盾事实标失效、留历史）；凭据/手机号/住址不进记忆（自动脱敏不覆盖这些）。

## 五、自动化（08）

| 项 | 事实 |
|---|---|
| 入口 | `automation` 工具只有 `list` / `create` / `update`；**无 delete**（走面板） |
| 不直写 | `create`/`update` 只产**待确认建议**（`automation-draft-no-write`）；用户点确认或回 `/apply [短码]` 才落库（**"确认"二字无效**） |
| 类型 | `at`（一次性）｜`every`（分钟）｜`cron`（5 字段） |
| 硬墙 | 单次执行**超时 20 分钟** → 治理任务必须**分批 + 幂等 + 可断点续扫** |
| 出生地不可变 | 任务 cwd 回**源会话**解析；源会话没了任务报错 → **只能重建，不能改写** |
| prompt 主从双写 | 顶层 `prompt` 是主源；改 prompt 只认 `automation update` |

## 六、失败分科（08 §6）

先看 `cron-runs` 的 error 字段判科再动手：模型/网关 · 超时（改分批） · 出生链断（重建任务） · cwd 漂移（prompt 第〇步核） · schema 不符（等平台）。
