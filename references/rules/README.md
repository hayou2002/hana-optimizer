## 0 这套文档是什么

把散落在设计蓝图、skill 手册、历史巡检踩坑里的治理规则，提炼成一套**分三部分**的规范：

> **调查（01/02/03/06）→ 策略（04/05/07）→ 自动化（08）**
> —— 认识对象 → 制定怎么动 → 让它自己按节奏发生。

目的只有一个：**任何一次「往工作区写东西 / 清理东西 / 找东西」的动作，都有唯一明确的规则可依**，不再依赖每次临时判断。

三条底线贯穿全篇：

1. **单一权威**——同类规则只有一个定义处，其余位置只引用不重写（防"抄本漂移"，史上栽过）。
2. **去向与去留分开**——**扫描与分类在 04 → 去向在 05 → 时钟与通道在 04**（三段式；只有单件当场裁决才"先去向、后时钟"）。
3. **护栏在现场动作流程，不在提示词里**——所有动手动作走同一套 `扫描 → 出方案 → 确认 → 执行`，对话、定时任务两条入口谁都绕不过。
4. **扫描、制定与执行在 AI 或人**——本 skill 无引擎，Agent 既是"脑"（语义扫描、方案、取舍）又是"手"（现场 `Get-ChildItem`/`Move-Item` 等命令）；三个法域统一流程：**扫描 → 分类 → 出方案 → 人拍板 → 执行 → 验证**。

**联动关系一句话版**

- **01 → 03**：01 给顶层白名单，03 是白名单内 `projects/{名}` 这一格的"内部装修标准"。

## 4 权威链与优先级（冲突时按此裁决）

```
① 现场实测 / 规则源      ← 实测压倒纸面；细则=rules.json；根=desk.home_folder；落点=平台默认（01 §6.1）
② 本规范集（01~08）       ← 面向执行者的可读规范
③ 会话临时判断            ← 仅在 ①② 未覆盖处生效，且应尽快回填到规范
```

**机器规则不是一处**：清理细则（生命周期/白名单/保份数/风险档/阈值/豁免）在 `rules.json`；**默认工作区根**在 Agent 配置（`desk.home_folder`）；**平台默认落点**由平台内核固定（01 §6.1）。**冲突时现场实测压倒任何纸面文档。** **改任一处必须同批改其上下游**，否则即漂移。
