## 1 定位：两类工作文件夹，一个判据

一个"专项工作"（一次交付、一个项目、一条产品线）落在磁盘上，只有两种住处：

| 类 | 位置 | 例子 |
|---|---|---|
| **里面**（工作台内项目） | 主工作台的 `projects/{名}/` | 各本地项目（`{项目名}`） |
| **外面**（独立工作文件夹） | 工作台外，以**挂载**形式并列加入 | `<外部根>` |

**两者结构相似，位置决定待遇。** 写进本文件的一句判据：

> ### 读写平等，上下文不平等。

- **读写平等**：挂载层完全并列——三条记录结构同构（同一个 Studio、同一组 `capabilities: [list, read, write]`、同样 `status: active`），**没有任何 priority / primary 字段**；沙盒里落在这三个根里都判 `FULL`（可读写删移）。
- **上下文不平等**：平台自带的"自动行为"**只认主工作台**（`desk.home_folder`）——自动落点、`AGENTS.md` 注入、项目技能发现、`default` 根不可移除，全部锚它。外部工作文件夹在这些机制里**等于不存在**。

**实践后果**：你能在外部根里正常干活，但**别指望平台替你管家**（不会自动替你归位、不会自动注入它的项目规则）。

## 2 三层身份与法域（机制）

| 词 | 实质 | 存在哪 |
|---|---|---|
| **工作台** | 会话的**主工作目录** = `desk.home_folder`（agent 级配置）。UI 标"主 Agent 的工作空间"，带 `isDefault: true` | `agents/{id}/config.yaml` |
| **工作文件夹** | 并列添加的其它目录。两条并存通道：会话级 `workspaceFolders`（**进 prompt**）＋ Studio 级挂载（**进挂载注册表**，可长期引用） | session manifest / `studio-mounts.json` |
| **挂载（mount）** | ResourceIO 的可寻址根：`{kind:"mount", mountId, path}`。`mountId` 是**持久身份**，路径只是需重新验证的**定位器** | `studio-mounts.json` |

**关系链**：`server-node → user → studio → mounts[]`；另一条平行线 `agent → desk.home_folder → default 根`。列工作台时**先把 default 根当第 0 项插入，再追加所有 active mount**——所以同一个目录可能**双身份**（既是 `default`，又是某个 `local_fs_*`）。

**法域阶梯**（沙盒）：
- 落在 `workspaceRoots`（= 主 cwd ∪ workspaceFolders ∪ authorizedFolders）内 → **FULL**（读写删移）
- `HANA_HOME` 内 → **READ_ONLY**
- 两者之外 → READ_ONLY（开了外部读）或 **BLOCKED**
- `delete` 需 FULL，`stage` 只需可读；每个工作区根的 `.git` 列入 `protectedPaths`

**几条硬机制**：
- UI「添加文件夹」只接受**已存在的绝对目录**，固定写 `capabilities: [list, read, write]`；同路径重复添加幂等。
- **「移除」只把 `status` 置 `disabled`**，记录留盘；`default` 根**禁止移除**。
- 会话 cwd 决定顺序：显式 `cwd` 或 `workspaceMountId`（同时给报错）→ 写 `last_cwd` 与 `cwd_history`（上限 10）。**切换挂载或添加文件夹不会改任何已有会话的 cwd。**
- **≥ 0.971.2 的四条隔离**：不复制（选择只成为会话范围记录）／编辑写回原目录／只认本视图选过的目录／禁符号链接越界（统一 realpath 比对）。

> ⚠️ **术语警示**：`workspace` 在本产品被重载三次——文件工作台 / 卡片布局快照 / App 隔离环境。读代码或文档时别混。

## 3 【里面 vs 外面】差异对照表 ★

整理时**先问一句"它在工作台里面还是外面"**，就不会归错位、也不会漏内容。

| 维度 | 里面（`projects/`） | 外面（独立工作文件夹） |
|---|---|---|
| 位置 | 主工作台根内 | 独立挂载根 |
| 谁管 | **本规范**（白名单、四问决策树） | **只受挂载授权约束**（本规范管不到） |
| 平台自动区 | 有（`OH-Works/`、`OH-媒体库`、`魔术卡`） | **没有**——平台不会替你建目录 |
| 时钟 / 反悔区 | 有（`_temp` 生命周期、反悔区） | **无**（除非走 04 §9.1 解锁） |
| `AGENTS.md` 注入 | 沿主工作台目录链**自动注入** | **不自动**——要各自放一份 |
| 项目技能发现 | `.agents/skills`（只扫主工作台） | **不参与** |
| 入口件 | `项目索引.md`（**必须**） | `README.md` ＋ `项目说明.md`（等价） |
| 归位方式 | 四问决策树 → `projects/` | 显式指定目录／绝对路径（四问 Q2） |
| 默认落点锚 | 平台自动落点锚**主工作台** | **同样锚主工作台**→外部根不会被平台自动写入 |

## 4 通用骨架（两类共用）

结构相似，一起讲。但**格位要补齐三样过去没有的东西**：

```
{工作文件夹}/
├── 【入口件】        项目索引.md（里）｜README.md + 项目说明.md（外）
├── 【源码格】        src/  lib/  app/  pkg/  skill/
├── 【产物格】        dist/        ← 唯一名字，历史份数 ≤2，旧版走 storage/存底 或 git tag
│                                 ✗ 禁止 dist2/ dist3/ dist-final/ 并存
├── 【运行态格】      world/  data/  logs/  *.db  ← 不可再生资产
│                                 · 不进 git · 不进清理时钟 · 体积必须登记
├── 【文档格】        docs/  README.md  项目索引.md  开发反思.md
├── 【脚本格】        scripts/  Makefile  *.ps1/*.sh
├── 【环境格】        node_modules/  .venv/  .env（本地，不入库）
└── 【忽略件】        .gitignore    ← 必选件（见 §4.2）
```

### 4.1 三条格位纪律

1. **产物格用唯一名 `dist/`**，历史份数 **≤2**（当前 + 上一版）；旧版**不进目录**，走 `storage/存底/` 或 git tag。五套 `dist*` 并存属于违规。
2. **运行态格单列**：`world/`（游戏存档）、`data/`（数据库）、`logs/` 是**不可再生的现场**——既不是源码也不是产物，**不进 git、不进清理时钟**，且体积要登记。这是本文件补上的最大空洞。
3. **命名**：小写英文 + 连字符，或明确中文名；**禁止把状态、版本、日期写进目录名**（`-active`、`-1.8.1` 会让改名即断链）。

### 4.2 `.gitignore` 升为骨架必选件 ★

已有不少项目与外部根在用，但规范从未写。**必排清单**（模板见附录 A）：

`node_modules/` `dist*/` `build/` `out/` `*.log` `*.tmp` `__pycache__/` `.env*` `*.key` `*.pem` `*.exe` `*.db*`

两条附加纪律：
- **二进制入库必须显式声明理由，并写选择性排除**（正面样板：某外部根的 `.gitignore` 只排历史归档件、保留现行发布件）。
- **凭据红线**：`.env` / `*.key` / `*.pem` / `secrets*` 永不入库（正面样板：某仓库的 `.gitignore`）。
- 锁文件：**应用类项目入库**（要"今天能跑=明天 clone 也能跑"）；**库/技能类不入库**（按生态惯例）。

## 5 编程类专项（三条判断轴）

一个项目"什么该入库、什么该忽略"，不问口诀，问三个问题：

| 轴 | 问题 | 结论 |
|---|---|---|
| **重生命** | 删了能否凭已入库的东西 100% 重建（`npm i`/`pip install`/`cargo build`）？ | 能 → 不入库 |
| **确定性** | 它是"意图"还是"某台机器某一刻的快照"？ | 意图入库，快照不入库 |
| **敏感性** | 有没有密钥、token、真实用户数据？ | 有 → 永不入库，走 `.env` + 模板 |

**落哪一层**：项目内（跟项目绑定）｜工作区层（跨项目共享的个人偏好、通用脚本）｜外部总部（体积大/无关/需独立备份：全局环境、SDK、工具链、素材原件）。

**逐类速查**：

| 类别 | 入库 | 例子 |
|---|---|---|
| 源码 | ✅ | `src/ lib/ app/ pkg/ cmd/ internal/` |
| 依赖清单与锁 | ✅（应用） | `package.json`(+lock)、`requirements.txt`、`pyproject.toml`、`go.mod`/`go.sum` |
| 环境 | ❌ | `node_modules/`、`.venv/`、`.env`（`!`.env.example` 入库） |
| 构建产物 | ❌ | `dist/ build/ out/ target/ .next/ __pycache__/ *.egg-info/ *.vsix *.asar *.exe` |
| 工具配置 | ✅ | `.gitignore`、`.editorconfig`、`tsconfig.json`、eslint/prettier |
| 脚本 | ✅ | `scripts/`、`Makefile`、`*.ps1/*.sh`（路径必须相对仓库根） |
| 测试 | ✅（覆盖报告 ❌） | `tests/ __tests__/`；`coverage/ .pytest_cache/` 忽略 |
| 文档 | ✅ | `README.md`、`docs/`、`CHANGELOG.md`、`LICENSE` |
| CI/容器 | ✅ | `.github/workflows/`、`Dockerfile`、`docker-compose.yml` |
| 数据/样本 | fixtures ✅ / data ❌ | `fixtures/` 入库；`*.db *.sqlite data/` 忽略 |

**本地环境产物 vs 可交付产物**：`dist/` 同一个名字，本地 build 调试=环境产物（忽略），CI 打完包发出去=可交付产物（归档）。**规范做法**：交付物从 `dist/` 拷进带版本号的 `release/{名}-v1.2.0/`，那份进外部总部；`dist/` 本身永远忽略。

**常见坑**：Windows 260 路径（浅根 + `core.longpaths`）、**仓库内一律 ASCII**（中文进 README 与归档层）、lock 冲突别手改、大文件 >10MB 离开 git、`.env` 泄密先轮换密钥。

## 6 位置差异带来的规则差异（操作层）

### 6.1 里面
走 **01 §4 四问决策树** → `projects/{名}/`；受 `_temp` 时钟、反悔区、白名单约束。

### 6.2 外面（外部工作文件夹的独立规矩）

**红线**：外部文件夹**不参与平台自动落点**——Agent 在外部根里生成产物时，必须**显式指定目录或用绝对路径**，不要期待平台帮忙归位。

四条独立纪律（样本取自现成实践）：
1. **入口件二选一**：`README.md` + `项目说明.md`（与里侧的 `项目索引.md` 建立**等价映射**，别让"必须项"在外侧失效）。
2. **必须写「仓库分工」段**：谁是**纯本地快照**、谁是**脱敏档案仓**、谁收容**大二进制**（样板：某外部根的 `README.md`）。
3. **每个根自带「路径腐烂扫描」条款**：搬迁/合并/删除后 grep 旧路径逐条分流，**只信实测不信记录**。
4. **大件素材落归档目录**（如 `<外部根>` 下的归档位），不塞进工作文件夹。

### 6.3 双身份与移除
- 同一目录可能同时是 `default` 与 `local_fs_*`——规则文档引用路径统一用 `default`，避免两套 ref。
- **「移除」≠ 删除**：只置 `disabled`，`mountId` 与声明留盘，重加同路径拿回同一 id。

### 6.4 外部的扫描与清理（归 04）★

外部法域**没有自动化清理通道**，但不是不管：
- **节奏**：**每日**随「每日治理巡检」做**只读**巡检（零写入）；**每季**深度盘点。
- **扫描**：只读盘点（04 §3.1）——入口件、`dist*` 多版并存、环境、运行态、临时件、散落件、旧路径腐烂、同类根关系、大文件。
- **方案**：AI 出三档方案（可现清 / 需确认 / 绝不碰）。
- **执行**：默认人；许可时 Agent 按方案执行。**默认不留反悔区**（要留退路须先走 04 §9.1 解锁并以人批准为条件）。

## 7 停用 / 归档档位 ★

本文件补上过去没有的档位：**项目索引.md 加一节「三态账」**——

| 态 | 含义 | 例子 |
|---|---|---|
| 本机安装态 | 这台机器上跑着的 | `skills/` 里已装的包 |
| 工作仓 | 正在维护的源码/文档仓 | `projects/*`、`<外部根>` |
| 归档 / 停用 | 被取代、暂停，但不可再生资产在 | 某停用项目（不可再生运行态数据仍留） |

停用项目**不删**，但必须登记状态与不可再生资产位置；实体可迁 `storage/存底/`。

## 8 与其它文档 / 系统的联动

- **01**：里面走 01 白名单与四问；外面是 01 §4 Q2 的落点（"运维/产品线 → 外部总部"）。

- **AGENTS.md**：生效范围 = **会话的主工作目录（cwd）链**（向上至 git 根），**不跨根汇总**。里侧（主工作台）自动注入；外侧**不自动**——**每个根各放一份**（部分外部根已有自己的 `AGENTS.md`，属其自治），别在主工作台写"总管规则"指望覆盖外部。**两者不冲突**（服务不同 cwd 的会话）。

## 9 待优化与未核实

- **Windows 下 `.git` 写保护强度**：策略层声明保护，Windows 分支把根级 `.git` 从 `denyWritePaths` 过滤掉了，**执行强度待验证**。
- **顶层计数与实况**：`projects/` 与外部根的项数会变；同一产品线常拆成多个平级根，**无一份文件说清谁是真身、谁镜像**。建议立"唯一事实源 + 辅仓"声明字段。
- 桌面上的散根（不在挂载内的独立目录）属第四类，尚无归属；建议由某个专项的索引**反向登记**。
- `UI「添加文件夹」写进哪一层`（挂载 or 会话）未读通渲染层。
