## 1 自动化机制（automation）

| 项 | 事实 |
|---|---|
| **入口** | `automation` 工具只有 `list / create / update`；**无 delete/pause/resume**（那三个只在面板 HTTP / UI） |
| **不直写** | `create`/`update` **只产出待确认建议**（`ruleId: automation-draft-no-write`）；用户点确认卡或回 `/apply [短码]` 才落库（**回"确认"二字无效**） |
| **类型** | `at`（一次性 ISO，跑完自动 `enabled=false`）｜`every`（分钟，下限 60s）｜`cron`（5 字段表达式） |
| **调度** | tick **60 秒**；逐 job 查 `nextRunAt <= now` |
| **硬墙** | 执行**超时 20 分钟**（`Promise.race` abort）；`consecutiveErrors` +1 并按 `0/1/5/15/60m` 退避 |
| **流水** | `cron-runs/{jobId}.jsonl`（超 500 行截尾 300 行）；`desk/activities.json` 摘要 |
| **隔离会话** | 以独立后台 session 跑（`domain:activity`）；`approvalPolicy: deny_on_prompt`（**需人工确认的动作直接返回 unavailable，不弹窗**）；记忆系统照常加载 |
| **prompt 主从双写** | 顶层 `prompt` 是**主源**；`executor.prompt` 会被归一化覆写成同文。**改 prompt 只认 `automation update`；手改 json 的 executor → 下次任何变更即被覆写** |

> **超时墙的推论**：任何"一次扫全量"的 prompt 必然死于 20 分钟墙下 —— 所以治理任务必须**分批、幂等、可断点续扫**（现有"补跑自愈"设计正是对墙的适应，本文件把它升为**通则**）。

## 2 任务的「出生地」不可变 ★（cwd 回源）

隔离任务的运行 cwd **不读任务里存的字面值**，而是 `_resolveCronExecutionScope`：**有源会话 → 回源解析它的 folder scope**；源会话不可用 → **任务直接报错**；无源会话 → 取 Agent 的 `desk.home_folder`。

**实证要点**：任务的 `executionContext.cwd` 字面值**不决定**运行 cwd——实际值回源解析自**源会话**的头一行；源会话 cwd 指向何处，运行与产物就落何处。这是机制，不是故障。

**两条正解**：
1. **prompt 层防御**：**所有治理任务**第〇步 `(Get-Location).Path` 核对 + 全绝对路径（见 §4 模板）。
2. **结构迁移后重建任务，而非改写任务**（工作台搬迁、旧目录废弃等场景）。

## 4 任务通用模板（所有治理任务通用）

```
第〇步 开工核对 + 根发现（硬闸）：(Get-Location).Path 核对；读 studio-mounts.json 取全部 active+write 根（主工作台 = desk.home_folder；外部根 = 其余）。不符/读不到 → 只读 + 最小检查点 + notify，零执行。
一、范围与白名单（主工作台六格 + 平台常驻户；外部根只读；旧结构过渡豁免；缺格不建不搬）
二、按使用情况分级：活跃（≤3d）深扫 / 温（3~30d）出方案 / 休眠（>30d）轻扫
三、规则唯一源：rules.json（不内嵌映射/数值）
四、只读扫描：现场扫描（`Get-ChildItem`）→ Agent 出三档方案（禁递归全量列文件）
五、执行：仅 safe 档（现场 `Move-Item` 进反悔区，只限主工作台）；confirm/report 档只列不动；外部根零写入
六、只报告法域：本体 / 外部（零写入）
七、联动更新（§5）
八、指针复核（`Test-Path` 实测）
九、沉淀：检查点三表（均含「法域」列）
禁则：创建新任务 / 递归全量列 / 绕方案手改 / 对话内手工出清 / exec 直删 / 动常驻户 / oversized 进删除计划 / 外部根写入
```

> 模板只写语义；**根动态发现（App 设置 + 挂载表）**，**路径全绝对**，**分批幂等**（对超时墙；多根时主工作台必扫、外部根浅扫或轮扫）。

## 5 联动更新（核心）★

**问题**：删/搬/改之后，**记录里还记着旧位置**——经验、记忆、文档、注册表、任务 prompt。不跟着改，记录就会一直骗下一个消费者（呼应 06/07"只信实测不信记录"的另一面）。

**触发**：本轮**实际发生移动/删除**的项（判据：本轮实际发生搬移；`pendingSync` 记在 App `clean-history.json`）。

**载体清单（05 §5 八步 → 08 扩为「十步」）**：

| # | 载体 | 谁管 |
|---|---|---|
| 1 | **pinned 记忆**（`search_memory` 定位 → `unpin`+`pin`） | 07 |
| 2 | **经验库**（`recall_experience` 查重 → `record_experience`） | 07 |
| 3 | 其它 SKILL.md / README / 项目索引 / 开发反思（grep 旧路径改写） | 05 |
| 4 | `rules.json` 归类表与落点禁区（读写 `<根>/.optimize/rules.json`） | 04 |
| 5 | cron prompt + 工作区根 `AGENTS.md`（走 `automation`；**主从双写**） | 08 |
| 6 | 外部根内引用 + 各根路径腐烂扫描 | 05 |
| 7 | 本体 `extensions/installs.json` 台账 + `agents/{id}` 技能引用 | 02 |
| 8 | git tag / 历史随迁核对 | 03 |
| **9** | **`preferences.json`**：① `workspaceRoot`（App 设置·真根源）② 工作区状态段（按路径为 key） | **08（新增）** |
| **10** | **`config.yaml`（home_folder/last_cwd/cwd_history）+ `studio-mounts.json`（挂载表）** | **08（新增）** |

**任务载体同步（第十一步·特例）**：cron 任务的 cwd 系于**源会话出生地**——八步能改 prompt，**改不了出生链**。源会话被清除 → 任务报错。**唯一修复 = 重建任务**（从一个 cwd 正确的会话里重新 `create`）。此步**不可用同步解决**，只能登记为"待重建"。

**故意不同步的（写明即可，免得心虚）**：`session-manifest.db`、`file-history/`、`opened-documents.json` —— 属历史事实，设计上不回写。

**漏改的兜底**：`Test-Path` 现场实测（§7 模板第七步）——**只信实测不信记录**。

## 6 失败分科与处置树

**先看 `cron-runs` 的 error 字段判科，再决定动作**：

| 科 | 症状 | 处置 |
|---|---|---|
| **模型/网关** | `model 不可用` / `价格未配置` | 换 `executor.model` 或等网关 |
| **超时** | `execution timeout (20min)` | 改 prompt：**分批 + 幂等 + 断点续扫** |
| **出生链断** | `source session unavailable` | **重建任务** |
| **cwd 漂移** | 产物落非预期目录 | prompt 第〇步核对（已拦）；根治要重建 |
| **schema 不符** | `skipped: unsupported_automation_schema` | 平台升级适配 |

> 常见真实案例：`consecutiveErrors` 记 1，落在**超时科**（处理见上表）。

## 9 与现场对接时的注意事项

1. **联动清单十步**建议与 05 §5 保持单一源。
2. **任务 prompt 与文档同批**：prompt 里若内嵌白名单/映射表，随规范修订同步更新（含第〇步核对、分批幂等、联动十步）。
3. **每月/每季任务**（本体/外部/知识域）按需真建，否则规则停在纸面。
4. **任务重建**：出生链指向旧工作台的 job，择机**重建**（不是改写）。
5. `preferences.json` 的工作区状态段与旧路径条目尚无扫描/清理条款——迁移后按「关联同步」清单手工跟进。
