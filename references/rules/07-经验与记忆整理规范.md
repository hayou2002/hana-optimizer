## 0 定位与与 06 的分工

**06 定"住哪 × 格式 × 通道"；07 定"时钟 × 操作 × 验证"。**

```
识别（按 06 契约：真源/派生、对象台账）→ 判定（本文件九项操作）
→ 执行（走工具/HTTP/文件面，见 §7）→ 验证（回 06 校验 + 本文件 §6）
```

**为什么要整理**（典型退化见 §1，均有真实样本）：产生面有五条通道持续写入，而**遗忘机制只覆盖其中一层**——剩下的会**只进不出**，最终把记忆变成"负债"而非"缓存"。

---

## 1 要解决的问题（七种典型退化）

| # | 退化模式 | 典型表现（示例） |
|---|---|---|
| G1 | **陈旧冲突** | 两条同主题 pin（旧条记录旧状态、新条记录新状态与迁移）并存打架；旧条目无"被取代"标记 |
| G2 | **置顶凝结成大单件** | 一个大单件里事实/教训/纪律混灌一条——局部过时=整条过时；且**无 update 工具**，只能整条撤再重钉 |
| G3 | **双源漂移** | `pinned-memory.json` 与 `pinned.md` 无一致性校验；字段可缺 |
| G4 | **经验库只增不减** | 类目偏细、**单条类占比高**；粒度交叠（如"docker运维/容器部署/服务器运维"）；工具面无 delete/merge |
| G5 | **编译链断档** | `daily/` 指纹与正文天数不符；`week.md` 缺日；**断档无人报警** |
| G6 | **整理引擎静默失败** | Dream 可超时失败（`LLM_TIMEOUT` failed、`changed=false`），**无重试无补跑**（对比：归类任务有"缺跑自愈"） |
| G7 | **长尾无盘** | `summaries/`、`daily` 指纹、迁移留底——**02/04 的扫描清单都不含知识法域内部** |
| G8 | **预算挤占** | 事实层膨胀→编译视图超预算→截断不可控；`pinned` 全文常驻，是最大压力点 |

> **G8 的终局**：记忆退化成"负债"——逼每个消费者回现场复核（呼应 06"只信实测不信记录"）。

## 2 整理操作九项 ★

每项给：判据 → 通道 → 可逆性 → 执行者。**执行者统一为「AI 出方案、人拍板」**（对齐 04 §4.2 本体式通道）。

| 操作 | 判据 | 通道 | 可逆 |
|---|---|---|---|
| **① 去重** | 语义等价（Dream 的 `same_meaning`） | 文件面 / Dream | 手工删可撤回（revision） |
| **② 合并** | 同一主题多条（`subsumes`） | 文件面 / Dream | 同上 |
| **③ 拆分** | 一条混装多主题（如 pin 服务器条） | 改 `pinned.md`（md 反超 json 生效） | 是 |
| **④ 降权（下沉）** | pin 里是"操作手册/纪律"而非"关系事实" → 下沉到经验库或工作区文档 | 改 `pinned.md` + `record_experience` | 是 |
| **⑤ 退役（取代标记）** | 矛盾事实（新值取代旧值） | **无原生通道** → 手动在正文标注"（已被 X 取代）"或删旧 | 是（可恢复） |
| **⑥ 删除** | 仅三种客观理由：`completed_transient`/`obsolete`/`operational_noise` | 文件面 / `DELETE`（整库）| **物理删=不可逆** |
| **⑦ 消冲突** | 同一事实两处说法不同 | 定权威源，另一处标失效 | 是 |
| **⑧ 类目治理** | 单条分类、近义分类 | 改文件名/正文 + 刷新 `experience.md` | 是 |
| **⑨ 格式修复** | 缺字段、base64 title 坏、hex-id 错 | 文件面 | 是 |

> **删除的铁律**（借 Dream 的克制）：**证据不足一律保留**；禁止按比例/条数/年代/"听起来不重要"删。**"取代 ≠ 删除"**——矛盾事实优先标失效、保留历史。

## 3 分层归属判据（放对层，才不会被自动删）

平台的分界很明确，整理时顺着它：

| 内容 | 该去 | 不该去 |
|---|---|---|
| 用户是谁 / 喜欢什么 / 在意什么 | `facts.md` / `longterm.md` | 经验库 |
| 最近关注哪个大主题 | `today` / `daily`（**只到主题级**） | longterm |
| 以后遇同类任务该怎么做（工程纪律、路径、命令） | **经验库或技能** | **记忆层**（会被 Dream 判 `operational_noise` 删掉） |
| 钉住的关系事实/长期约定 | **`pinned`**（人工专属层） | 记忆四段 |

> ⚠️ **放错层 = 白写**：把工程纪律写进记忆层，Dream 会当噪声删；想长期留的东西放对层。

## 4 时钟与触发线

**触碰式触发**（结构化真源，走通道）：
- `hours / pin 字数上限`：`pinned.md` 应设显式上限（常见量级可远超四段记忆全文，是人工常驻的 token 压力点）；超限 → 下沉/合并。
- `条/类上限`、`单类条目上限`：经验库（常见问题：类目偏细、单条类过半）。
- `Dream 触发`：平台自管（该逻辑日未跑过 + 无在途摘要 + ticker 带动）。

**事件式触发**：
- 实测到冲突（G1）→ 消冲突；发生取代 → 打失效标记；发现断链（指针失效）→ 修/删。

> 阈值数值先按现场基线起算，落地后再定终值。

---

## 5 失败检测与补跑（补 G6 的洞）

- **Dream 连续 N 失败 → notify**（有真实失败先例）。
- **编译断档检测**：`daily/` 正文天数 vs 指纹、`week.md` 缺日 → 报警（借归类任务的"缺跑自愈"概念）。
- 可核对项：`GET /memories/health` 的五步成功时间戳 + `dream/state.json` 的 `forgottenCount` —— 用来判断自动整理**最近是不是真的在跑**。

## 6 校验五件套（结构侧）

| 项 | 查什么 |
|---|---|
| 双源一致 | `pinned-memory.json` ↔ `pinned.md` |
| 索引↔正文 | `experience.md` ↔ `experience/*.md` |
| 必填字段 | `createdAt`、base64 title、hex-id 格式 |
| 指针复核 | 记忆里的路径实测（沿用 05 §6） |
| 敏感字段 | 手机号/住址/明文凭据扫描（**自动脱敏不覆盖这些**） |

### 6.5 Hana 自带的整理工具箱 ★

**用 Hana 自己的机制整理**——每个动作先挂到现成工具上：

| 机制 | 能做的整理 | 备注 |
|---|---|---|
| **Dream** | 去重 / 合并 / 降噪（限 `facts`+`longterm`） | 唯一语义整理器；三删除理由；revisions 留 10 版可回滚 |
| `PUT /memories/compiled/{facts,today,longterm,week/days}` | 改四段真源 | 走通道，安全 |
| `pin_memory` / `unpin_memory` | 置顶增删；**unpin 支持 keyword 批量命中** | 无 update（撕旧 + 存新） |
| `record_experience` / `recall_experience` | 经验记 / 查；record 刷新索引 | 无删改 API |
| **逻辑日 0400** | 日切：today 清空、daily 滚动 | 整理节奇对齐它 |
| `GET /memories/health` + `dream/state.json` | 判断自动整理是否真在跑 | 巡检探针 |

> 原则：**能用平台机制的，不手动改文件**；工具面覆盖不到的，才落到 §7 的缺口处理。外部借鉴（遗忘四策略等）仅作对照，见附录 A。

## 7 通道缺口与最小护栏 ★（本文件最该正面的）

**现实**：整理动作在**制度上正当**，但平台**没给通道**——`experience/`、`pinned`、`facts.db` 三个"只进不出"的对象**没有逐条 API**，Dream 只管 `facts/longterm`。

**三种合法路径**（按优先级）：

| 路径 | 适用 | 边界 |
|---|---|---|
| **① 原生通道**（首选） | Dream、`PUT /memories/compiled/*`、`pin/unpin`、`DELETE /memories` | 有回滚（revision / pending journal） |
| **② 文件面**（常规） | **仅 `pinned.md` 与 `experience/*.md`** 两处是常规操作 | 改前备份；改后回读；避开 SQLite 三件套 |
| **③ 人工设置页** | facts 可编辑段、`memory.enabled` 开关 | 撞 02 红门内的"合法面" |

> **红线**：不手改 `memory.md`/`week.md`/`experience.md`（派生）；不动 `facts.db` 的 `-wal/-shm`；不整库清（除非用户明确"忘掉"）。

**最小护栏建议**（呼应 README 底线 3"护栏在现场动作流程"——知识法域目前**零护栏**，全靠 prompt 自律）：
1. `pinned.md` 字数门禁（超限即告警）；
2. 双源一致性校验脚本（纳入巡检）；
3. `experience.md` 索引自动重生成（record 时已做，可扩到巡检）。

## 附录 A · 遗忘四策略 × Hana 现状（借鉴映射）

| 策略 | 外部做法 | Hana 现状 |
|---|---|---|
| **age**（绝对年龄） | TTL / 时间窗 | ✅ 6 天窗口滚动（daily） |
| **recency**（多久没碰） | 检索衰减 `0.995^Δt` | ❌ 无（无 last_access） |
| **salience**（低重要度） | 打分淘汰 | ❌ 无（分数机制是死键） |
| **supersession**（被取代） | 标 `t_invalid`，保留历史 | ❌ **无**（最大缺口，G1 的根因） |

> **可移植的三条**：① 给矛盾事实加**取代标记**（"取代 ≠ 删除"）；② `pinned` 全文常驻是**人工专属层**，纪律最严；③ 验收用**自建小样本**，别信厂商分数。

## 附录 B · `pinned` 整理样板

若 `pinned` 已凝结成大单件（常见：运维手册、事故教训、临时现场记录三类混装），按以下样板处理：
1. 逐条判层：关系事实留 `pinned`；操作纪律下沉**经验库**；临场状态下沉**工作区文档**。
2. 同类合并（`unpin` 支持 keyword 批量命中，可"一个关键词收一族旧条目"）。
3. 定字数上限，超限即下沉。
