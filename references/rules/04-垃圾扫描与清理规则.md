## 0 目标与非目标

**目标**：给三个法域一套统一的扫描与清理规则——**三个法域都扫描、都出清理方案，由人拍板怎么清**（执行者可以不同，但"看清 → 出方案 → 人决定"这条线三个法域一致）。

**AI 贯穿始终（本文件的根本分工）**：现场命令是**手**——只管规则能写死的活（计数、指纹比对、按写死规则命中、移动/软删/出清）；**AI 是脑**——管要看内容才知道的活（散件裁决、孤儿判定、唯一存底、方案组织与取舍、跨法域盘点）。**扫描权与制定权在 AI，执行须经人确认（限工作区）。**

**非目标**：不复述各法域的结构与"住哪"（那是 01/02/03 的职责）——本文件只做清理，结构细节一律**引用**，不重写（防抄本漂移）。

> v0.1 是"工作区操作手册"，照搬 v4 蓝图；v0.2 换骨架为 **"法域 × 扫描 × 分类 × 通道 × 验证"矩阵**。规则由 01/02/03 的调查结论**重新推导**，现场命令只是"工作区"那一章的执行者。

## 1 三法域一览（后面所有条款引用此表）

| 法域 | 根 | 扫描 | 清理方案 | 执行者 | 可逆性 |
|---|---|---|---|---|---|
| **工作区** | `OH-WorkSpace` | 现场扫描（`Get-ChildItem`，12 类） | Agent 三档方案 | **Agent**（人确认后执行现场命令） | 反悔区 + `.manifest.jsonl` |
| **Hana 本体** | `~/.hanako` | 现场只读盘点（扩展四分区）+ **体量长尾盘点** | **AI 三档方案** | **人**（关应用后手清） | 平台 `trash/`（无 TTL）+ `file-history/` |
| **外部工作文件夹** | `<外部根>` 等挂载根 | **只读盘点**（dist*/运行态/旧路径） | **AI 三档方案** | **人 / Agent 按方案** | 域内 `_temp/反悔区/` |

**一句话**：**三个法域都扫描、都出方案；只有工作区能"自动执行"，本体与外部由人拍板执行。**

### 1.1 三层分工：AI 贯穿始终 ★

| 层 | 管什么 | 覆盖法域 |
|---|---|---|
| **现场命令** | 规则能写死的：确定性计数、机械分类（junk/oversized/expired）、指纹比对、移动/软删/出清 | **仅工作区** |
| **AI（Agent）** | 要看内容才知道的：**语义扫描**（散件、孤儿、唯一存底）、**方案组织与取舍**、跨法域盘点、关联同步、验证复核 | **全部三个法域** |
| **人** | 拍板 | 全部 |

> **现场扫描只覆盖"确定性那半"**——能数、能比指纹、能按写死规则命中；但"这根散件是不是唯一存底""这个 `app-data` 是不是孤儿""这堆 `dist` 该留哪套"——**机器数不出，必须由 AI 判断**。所以：**扫描权与制定权在 AI，执行须经人确认（限工作区）。** 现场命令始终只是 AI 手里的一件工具，不是流程的主导。

## 2 统一分类（换汇层）★

三套旧词汇（三口径 / 三道门 / 格位）互不映射，先换汇成一层公共分类，再派生汇报口径。

### 2.1 按对象性质分四类

| 类 | 定义 | 例子 |
|---|---|---|
| **① 可再生** | 删了能自动长回来 | 各类缓存、构建产物、环境格（`node_modules`/`.venv`）、市场下载、`model-catalog` |
| **② 到期** | 有生命周期且已超龄 | `_temp` 时钟项、日志、冷会话缓存、归档会话、迁移备份 |
| **③ 孤儿** | 身份核验后无人引用 | 孤儿 `app-data`、`staging` 旧包、空壳目录、散件 |
| **④ 不可再生** | 删了就没了 | 运行态（`world/`/`data/`）、唯一存底、凭据、会话正文、上传原件、`artifacts` 内被引用的版本 |

### 2.2 挂两个轴

- **执行者**：平台自清 ｜ Agent 动 ｜ 引导手动 ｜ 不动手
- **可逆性**：反悔区可回 ｜ 历史库可回 ｜ **不可逆**

### 2.3 派生汇报口径（工作区体检用）

| 口径 | = 四类中的 | 含义 |
|---|---|---|
| **可释放** | ①② ＋ ③中可机械判定项 | 真会从磁盘消失 |
| **待归位** | ③ 中的语义类散件 | 搬移类，挪了不省空间（**不计入可释放**，防虚高） |
| **仅报告** | 平台自清项 ＋ ④中"清不动" | 不需要或不该由你清（**不产生机器可执行计划**） |
| **绝不碰** | ④ 红名单 | **独立口径**，与"仅报告"分开 |

> ⚠️ 旧词"**待裁决**"已**禁用**（它同时指已退役的 `_temp/待裁决` 目录、动作项清单、搬移类三义）。动作项清单一律叫 **"待办裁决列表"**（05 §4.3）；搬移类汇报口径叫 **"待归位"**。

## 3 扫描矩阵（扫什么）

| 法域 | 扫什么 | 工具 | 输出 |
|---|---|---|---|
| **工作区** | 12 类 findings（见附录 C） | 现场扫描（ResourceIO 快照 + 确定性规则） | 健康分 / findings / 可释放 / 待裁决 / 仅报告 |
| **Hana 本体** | ① 扩展四分区（apps/skills/recipes/extensions）+ selfManaged 五目录体量（`logs`/`uploads`/`.ephemeral`/`artifacts`/`plugin-backups`）② **体量长尾扫描**：审计日志年龄、`trash` 批次年龄、`.cache`/`model-catalog`/`staging` 字节数 | 现场只读盘点（`Get-ChildItem` + `Measure-Object`） | **AI 出三档方案**；不产生机器可执行计划（"只报告"＝不进自动执行计划，≠ 没有方案） |
| **外部工作文件夹** | **只读盘点**（见 §3.1） | Agent 只读 + `ls`/`grep` | AI 三档方案，交人 |
| **知识法域**（第 4 法域） | 记忆/经验：pin 字数、经验类数/条数、`summaries`/`daily` 计数 | 只读统计（`GET /memories/health`、`dream/state.json`） | AI 出方案、人执行（**07**） |

### 3.1 扫描清单（三法域都"好好扫"）★

**工作区**：12 类 findings（见附录 C）——散件、`_temp` 超龄、检查点/日志/存底超份、junk、oversized、idle 工具、空目录、inbox 滞留。

**Hana 本体**：
- 扩展四分区（`apps`/`skills`/`recipes`/`extensions`）：实存 + `installs.json` 差集、孤儿、同名冲突、静默失效
- `selfManaged` 体量：`logs`/`uploads`/`.ephemeral`/`artifacts`/`plugin-backups`
- 长尾：审计日志（`security-audit.jsonl`/`resource-audit.jsonl`）年龄、`trash/` 批次年龄、`.cache`/`model-catalog`/`staging` 字节
- 三道门映射（02）；凭据区跳过（`security/`、`*auth*` 等只列不读）

**外部工作文件夹**（必扫项）：
- **入口件**：`README` / `项目索引` / `项目说明` 是否存在
- **产物类**：`dist*` / `build` / `release` / `portable` **多版并存计数**
- **环境类**：`node_modules` / `.venv` / 锁文件体量
- **运行态**：`world` / `data` / `*.db` 体量 → 对登记表
- **临时件**：`_temp/` 内容与年龄
- **散落件**：根上非目录文件、无归档位的散件（如 `_temp$n.png`）
- **旧路径腐烂扫描**：grep 旧路径，逐条分流（真实引用→改写；历史注记→保留；判不准→实测）
- **同类根关系**：同一产品线的多个平行根有无"事实源/镜像"声明
- **大文件**：>10MB 清单

## 4 统一流程与三种执行者（怎么清）

### 4.0 统一流程（AI 驱动，三法域一致）★

```
AI 发起
 ① 扫描   现场扫描出确定性数据（计数/体量/规则命中）  ＋  AI 做语义发现（散件/孤儿/存底）
 ② 分类   现场命令给浅分类（junk/oversized/expired）   ＋  AI 定语义类（§2 四类对象）
 ③ 出方案 AI 给机械项（safe）                          ＋  AI 组织完整三档方案（含取舍/跨法域）
 ④ 人拍板
 ⑤ 执行   工作区：现场 Move-Item 进反悔区（AI 监督）  本体/外部：人 / Agent 按方案执行
 ⑥ 验证   AI 复核（体量 diff + 引用完整性/断链）  ＋  写检查点
```

**关键**：现场命令只负责①②③里的"确定性半边"；**"语义半边"和方案的成形始终属于 AI**。三个法域都走这条线，差别只在"执行者"与"可逆性"。

**方案格式（三法域统一）**——每个法域的扫描结果都按三档呈现：

| 档 | 内容 | 给人看什么 |
|---|---|---|
| **可现清** | 可再生 / 到期 / 孤儿 | 逐项 + 位置 + 预期释放体积 |
| **需确认** | 语义类 / 涉引用 / oversized | 逐项 + 影响 + 建议 |
| **绝不碰** | 不可再生红名单 | 只列名，说明为何不动 |

### 4.1 工作区：AI 出完整方案，现场命令执行机械项

**AI 先出完整方案**——不只三档方案里的 safe 项，还要把语义项（`rootStray` 待裁决、孤儿、唯一存底、oversized 取舍）一并组织进三档方案。**确定性项由现场命令执行。**

现有闭环全保留，**保护清单改为引用 01 §6.2 + §2.2 单一源**（消灭旧版把 `inbox` 列入保护、漏三常驻户的错）：

```
现场扫描（只读）→ AI 出三档方案（只读）
→ 用户确认 → 现场 Move-Item 进反悔区（写 .manifest.jsonl）→ 关联同步 → 检查点
```

- 反悔区放回 / 出清**只认默认根**（`OH-WorkSpace`）；现场实测（`Test-Path`）可对任意过护栏的根。
- 反悔区 → 按 `.manifest.jsonl` 手工放回 / 出清（硬删，唯一出口）；定时出清由 `sdk.tasks` 的 `purge-expired` 日巡。
- 两段式是硬的：根不一致 / 计划超 TTL(15min) / 规则变 / mtime+size 不符 → 拒执。

### 4.2 本体：AI 出方案，人执行

**扫描**：现场只读盘点（扩展四分区 + selfManaged 体量）+ 体量长尾盘点（审计日志年龄、`trash` 批次、`.cache`/`model-catalog`/`staging` 字节）。

**出方案**：按 02 三道门 + §4.0 三档，产出**"退出 Hana 后的清理方案"**（项、位置、**前提**、**自愈预期**、**回滚缺位**逐条列出）。

**执行**：**人**在退出 Hana 后手清（04 **不产生对本体的自动删除计划**）；需反悔窗口的跨法域移动，才走工作区反悔区（**镜像路径须显式写明**）。**执行权在人。**

### 4.3 外部：AI 出方案，人/Agent 执行

**扫描**：只读盘点（`dist*` 并存计数、运行态体积对登记表、**路径腐烂 grep**）。

**出方案**：同样三档（可现清：多版 `dist`/孤儿/缓存；需确认：运行态/涉引用；绝不碰：`.git`/凭据）。

**执行**：默认**人**决定；许可时可由 **Agent 按方案直清**。**默认只清"可再生"项、不留反悔区**（要留退路须先走 §9.1 解锁并以人批准为条件）。删除若需落地桶，用该域内自建 `_temp/`（**不要用 `resources.trash`**——那写进本体 `trash/`，无 TTL、平台无出清，不推荐）。

### 4.3 平台自清通道 —— 哨兵条款

平台已在自清约 80%（本体）。**04 不重复造轮子**，但设哨兵：**若某绿门机制失效**（如归档会话 90 天没清、冷会话 72h 没清），巡检报告要能抓到。

## 5 先决条件与护栏

**公共层**：根合法性（绝对路径/非盘根/深度≥2/实存/非链接/非家目录/**标记命中≥2**，执行前逐条现场核验）、mtime+size 复核、熔断（>30 项 / >200MB / >2 顶层）、symlink 逃逸拒绝、唯一存底门禁（`projects`+`storage/tools` 检索不到即 block）。

**本体专属**：**先退出 Hana**（`.ephemeral`/`file-history`/`logs` 被进程攥着）；**SQLite 三件同删**（`.db`+`-wal`+`-shm`）；动手前先做一轮现场只读体检。

**外部专属**：根级 `.git` 保护**待验证**（执行强度未知）；**一次一根**（反悔区操作绑默认根，切根走面板 `POST /api/root`）。

## 6 验证闭环（补齐旧版缺口）★

| 项 | 做法 |
|---|---|
| ① 逐件实测 | 删后逐件 stat（保留；Windows 删除会静默失效，故逐件删+核） |
| ② **体量基线** | 每轮清理**前后跑同一份只读盘点**，报"预估可释放 vs 实际释放"差值；**连续偏差 >20% 即规则回炉** |
| ③ 应用健康 | 本体清理后重启自检：台账 / 市场 / 模型目录能否自愈 |
| ④ 引用完整性 | 孤儿清理后扫断链：ledger、Agent 引用、被钉卡片路径 |
| ⑤ 回滚演练 | 每季度从反悔区 + 历史库各恢复一件 |

> **旧版最大缺口**：报"可释放 X"却从未实测校准。一个从未测过量的系统，报数字是空头支票。

## 9 待决与待优化

1. **外部法域是否纳入自动执行**：给 `<外部根>` 各补建一个 `projects/` 目录即可凑满 2 标记、**零规则放宽**纳入管辖（可选升级，本轮默认走引导）。**不建议**降 `requireMarkerCount=1`——护栏 1 防的就是对着任意盘乱剪。
