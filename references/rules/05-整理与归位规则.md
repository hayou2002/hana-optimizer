## 0 定位与握手协议 ★

**05 = 三法域「去向」的单一源**；04 = 「去留 × 通道 × 验证」的单一源。整理不是清理的子集，是同一批物件的另一个问题。

### 0.1 与 04 的分工（三段式，钉死）

```
① 扫描 + 分类（04）→ 产出名单：可释放 / 待归位 / 仅报告 / 绝不碰
② 去向（05）：对「待归位」定「搬到哪」
③ 时钟 + 通道（04）：执行现场搬移 / 软删 / 入反悔区
④ 关联同步（05）
⑤ 验证（04/05 共用）
```

> **只有"单个散件当场裁决"这一层，才成立"先去向、后定时钟"。** 作为总则应是上面的三段式（04 §2.3 在分类阶段就把"待归位"名单交出来）。

### 0.2 可单独跑

一轮整理**不依赖 04**：识别来源见 §2（各自引用 04/02/03），执行通道见 §4。04 提供"识别接口"，05 自带"判定—执行—同步—复核"全链。

## 1 第一条：负空间（什么不能搬）★

整理的第一课不是"怎么放"，是**"什么别碰"**。

### 1.1 Q0（保留名就地不动）
名字撞平台保留名（`OH-Works` / `OH-媒体库` / `魔术卡`）→ **就地不动，退出归位流程**。
> ⚠️ 这是**纸面防线**：若机器白名单尚未收编这三户（01 §9 检查清单所列为"必须加"），巡检若报这三户为散件，**一律不搬**。

### 1.2 禁搬清单（搬了救不回）

| 对象 | 为什么不能搬 |
|---|---|
| 平台常驻户三户 | `identityContract` **只认那一处路径**，搬动即断链；关联同步**救不回**（被钉卡片、媒体库资产会指向死路径） |
| 在册安装目录（`{name}-mcp/` 等被 `installs.json`/`mcp config` 引用的） | 平台在册资产，不搬不删不动 |
| `_temp` 根会话自建目录 | 到期前不搬（搬了别的会话找不到自己写下的路径） |
| 同级私档目录（`{项目}-工作笔记/`） | 项目索引已声明"过程文档放同级、不进公开仓"，**不并入 `docs/`** |
| 红门全体（02 §4） | 不可再生，删已不可逆，搬更无意义 |

### 1.3 本体豁免声明
`.hanako` 本体**物件路径即身份**，且 Agent 对其**只读**（过不了"源删除"闸）——**本体不做"归位"**，只做「**登记 + 引用修复**」。跨法域搬动一律禁止（要搬只能"复制出来 + 人删原"）。

## 3 判定去向

### 3.1 Q0＋四问（落点唯一入口）
见 **01 §4**：Q0 撞保留名→就地不动；Q1 projects／Q2 `<外部根>`（**须在挂载表且带 write**）／Q3 `_temp/时钟子目录`／Q4 inbox。

### 3.2 四类对象映射（判去向先判类）
| 类 | 去向倾向 |
|---|---|
| ④ 不可再生 / 唯一存底 | **优先识别，先于任何时钟落点分配**；进 `docs/{名}-待并入` 或归档位 |
| ③ 孤儿 | 同类重装？→ 保；否则归档位或删（04 判定） |
| ② 到期 | 进 `_temp/` 对应子目录（**注意：带时钟目录永不做现场自动落点**，见 §4） |
| ① 可再生 | 就地留（用时重建），不搬 |

### 3.3 出口白名单（inbox 裁决，五处——新增「归档位」）
1. `projects/`（按四问）　2. `storage/`（**过存底资格闸**）　3. `_temp/一次性/`（临时件）　4. 反悔区（勾删）　5. **归档位**（`storage/存底/` 或外部归档目录，走 03 §7 三态账登记）

> **唯一存底检测先于任何时钟落点分配**：§3.3 第 3 处不得吃掉唯一存底（§4.1）。已误落带时钟目录的件 → **立即移出**（补救路径，而非只禁止）。

### 3.4 散件三情形（各标对象类与三档归属）
- **唯一存底**（内容缺口保护）：`projects/{项目}/docs/{原名}-待并入.md`；整组保护、不得拆散、**绝不入一次性**。判据：对项目文件 grep 散件的表格行/小标题关键词，零命中即认定缺口。
- **classify 命中件**（限定自动归家）：扩展名命中 `rules.classify`（图像/脚本类）→ 自动归 `inbox`；`md/文档/未知` 维持 report-only。
- **待办裁决列表**（动作项常驻）：机械规则判不了风险的**动作项**，无时钟、只随勾选消除。**与 inbox 严格区分**（inbox 装文件，此表装动作项）。

## 4 执行（整理唯一的主动作）★

### 4.1 工作区：走现场搬移流程
现场出方案 → 用户确认 → 现场 `Move-Item` 进反悔区。**move（归家）与 trash（软删）同机制同留痕**：两段式 + TTL(15min) + `rulesHash` + 默认根比对 + 逐 op 的 mtime±1s/size 指纹 + 目标存在即拒（**永不覆盖**）+ 熔断（>30 项 / >200MB / >2 顶层）。

**出口的执行者**：`projects`/`storage` 是 `protectedPaths`，**自动搬移进不去**——§3.3 出口 1/2 **靠 Agent 执行**（`exec_command` 在 FULL 域内，或 `file copy` + 删源）；出口 3/4 进反悔区。

> **Agent 没有 `file move/rename/delete`**（`file` 工具只有 `stat/copy/extract`）——Agent 的搬运通道是 `exec_command`（FULL 域内）。

### 4.2 外部：人批准 → Agent 直移
外部根不在自动执行范围（标记不足）。归位＝**显式绝对路径** 下 Agent 直移（FULL），或走 04 §9.1 解锁。**默认无反悔区**。

### 4.3 本体：不搬
只产「**新路径登记 + 引用修复清单**」（§5 第 7 步）。扩展增删走 `extension_manager`（唯一合法通道）。

### 4.4 撤销窗口
按 `.manifest.jsonl` 反向 `Move-Item` 放回（prepared/moved 两态，倒序）。**原位被占用即拒**（不覆盖，保留反悔区）；无 manifest 的批次"不敢猜"跳过。→ **归家后别急在原位放新文件。**

### 4.5 禁则
- 禁止**绕过方案手动 `mv`/`rename`** 动工作区；
- 禁止**跨法域搬本体件**；
- 禁止把**带时钟目录当自动落点**（开工与执行前双重核验；人/Agent 手写落点不受此限，注意这条**不对称**）。

### 4.6 合并与改名
- 同名冲突：`-待并入` 标注（不覆盖）。
- **`dist*` 并版**：唯一名 `dist/`、历史份数 ≤2（03 §4.1）；旧版走 `storage/存底/` 或 git tag。
- 状态 / 版本 / 日期**不得入目录名**（`-active`、`-1.8.1` 会让改名即断链）。

## 5 关联同步（治理动作后必做，十步，顺序固定）

1. **pinned 记忆**：`search_memory` 定位 → `unpin_memory` 撤旧 + `pin_memory` 存新。
2. **经验库**：`recall_experience` 查重 → `record_experience` 更新。
3. **其它 SKILL.md / README / 项目索引.md / 开发反思.md**：grep 旧路径，命中则改。
4. **`rules.json` 归类表与落点禁区**（读写 `<根>/.optimize/rules.json`）——搬了目录不改映射 = 下轮误报。
5. **cron prompt 内嵌白名单 + 工作区根 `AGENTS.md`**（走 `automation` 入口）。
6. **外部根内引用 + 各根自带路径腐烂扫描**（grep 旧路径、逐条分流）。
7. **本体 `installs.json` 台账 + `agents/{id}` 技能引用**。
8. **git tag / 历史随迁核对**。
9. **`preferences.json`**：`workspaceRoot`（App 设置·真根源）+ 工作区状态段（按路径为 key）。
10. **`config.yaml`（home_folder/last_cwd/cwd_history）+ `studio-mounts.json`（挂载表）**。

> **特例（不可同步）**：cron 任务的 cwd 系于**源会话出生地**——只能**重建任务**，不能用同步修（见 08 §5）。
> **故意不同步**（写明即可）：`session-manifest.db`、`file-history/`、`opened-documents.json`。

**门禁**：搬移后必须做完这段再收工——**判据是本轮实际发生搬移的项**（记入检查点「关联更新」表，可回滚）。

## 6 验证

- **指针复核**：`Test-Path` 现场实测（**可对任意过护栏的根**使用；外部路径给绝对、跨法域分批复核）。**只信实测不信记录**。已知：`studios` 实测目录名是**完整 GUID**，记忆里的缩略写法不算腐坏。
- **引用完整性**：ledger / Agent 引用 / 被钉卡路径 / 挂载内旧路径 grep **归零**。
- **整理专用指标**：方案列出的件数 vs 实际搬移件数 vs 一次放回演练（搬移类体量 diff 恒为 0，**不写进验证**）。

## 7 检查点（每次治理后必写）

路径：`_temp/检查点/{YYYYMMDD}-归类检查点.md`，三张表（**表头增列「法域」**，使本体/外部轮次也能落同一份）：

| 表 | 内容 |
|---|---|
| 操作记录 | 这轮动了什么、怎么动（含法域） |
| 关联更新 | 同步了哪些引用（可回滚） |
| 指针复核 | 现场 `Test-Path` 实测结果 |

- **留痕**：现场 `Move-Item` 记 `.manifest.jsonl`；Agent 侧**自补检查点三表**。
- **正文用 `write/edit` 落盘**（禁 `Add-Content`）；保留 **10 份**；零发现 → 一句「工作区很干净 ⭐」。
- 时效原则：**早落地、后补记**；上轮结论一律本轮实测覆盖，不继承。

## 8 防漂移

| 内容 | 唯一定义处 |
|---|---|
| 白名单/生命周期/保份数/落点/风险档/阈值/豁免 | `rules.json`（读写 `<根>/.optimize/rules.json`） |
| 为什么这么定、踩坑、豁免登记、散件判据细则 | 项目维护者自持的人读手册（不随发布包） |
| 目录结构与温度 | `01-OH-WorkSpace结构规范.md` |
| 扫描与清理（三法域/四类对象/通道/验证） | `04-垃圾扫描与清理规则.md` |
| **去向与归位（本文件）** | `05-整理与归位规则.md` |
| **术语唯一源** | `README.md §3` |

- **改任一处必须同批改另一处。**
- **归类落点与落点禁区必须一致**（带时钟目录不得作自动落点）。
- **本文档不抄映射表**，归类表以 `rules.json` 为准。
- **巡检自己的手不能脏**：巡检产生的批量脚本、扫描输出、临时日志一律落 `_temp/一次性/session-debris-{当日}/`。

## 9 与现场对接时的注意事项

1. **规则表先收编常驻户**：`rootWhitelist`/`protectedPaths` 含平台常驻户（同 01 §9 检查清单），否则 §1.1 是纸面防线。
2. **任务 prompt 与文档同批**（同 08 §5、§9）。
3. **外部法域是否纳入自动执行**（见 04 §9）。
4. **05 与 04 的握手口径**：三段式（扫描分类→去向→时钟通道）为既定分工。
5. `autoRiskLevel`、`guard.migrate` 是**死配置**——本文件不依赖"风险档自动归位"或自动迁移机制。
6. **指针复核**可对任意过护栏的根使用（绝对路径、跨法域分批复核）。

## 附录 A · 一个件的完整生命周期（走查实例）

**根上一个散 `.md`（疑似攻略存底）：**

1. **04 扫描**：标 `rootStray`（report 档，非 autoHome 扩展名）。
2. **判类**：04 判它属 **④/唯一存底**（`projects`+`storage/tools` grep 零命中）。
3. **05 定去向**：`projects/{项目}/docs/{名}-待并入.md`（**不给时钟**）。
4. **04 定时钟与通道**：目标在受保护区 → **自动搬移进不去** → 由 Agent 执行（`exec_command` FULL / `file copy`+删源）。
5. **05 关联同步**：grep 旧路径（§5）；写检查点。
6. **验证**：现场 `Test-Path` 实测新位置；旧路径 grep 归零。
7. **检查点**：操作记录（法域=工作区）/ 关联更新 / 指针复核 三表。

> 一个件看完整套流程，是唯一能让人**验算 04 与 05 分工**的装置。
